# PromptEdit

AI image generation on top of the Laravel 12 + Vue 3 + Inertia starter kit. Images are generated by [Pixelforge](https://pixelforge.promptedit.dev/docs); users pay Pixelforge's actual cost plus a 25% markup.

## How it works

1. The user submits a prompt. The app validates it against Pixelforge's live pricing table (sizes, qualities), stores the generation with a worst-case cost estimate, and queues `SubmitGeneration`.
2. `SubmitGeneration` calls `POST /v1/generations` with the generation UUID as the `Idempotency-Key` and in `metadata`. Temporary errors (429 rate/concurrency limits, 503, timeouts) are retried with backoff, at least `Retry-After` seconds apart, up to 5 attempts. Rejections (content policy, validation, daily quota) fail the generation for $0.
3. Status updates arrive only by webhook (`POST /webhooks/pixelforge`); there is no polling. The scheduled `generations:resubmit-stuck` command re-queues submissions Pixelforge never accepted after 2 minutes.
4. The create response and webhooks both go through `GenerationStatusService::apply()`, which locks the row, never moves a status backwards, never changes a finished generation, and charges only on the transition to `succeeded`.
5. Succeeded images are copied to `storage/app/public/generations`, because Pixelforge URLs expire after 24 hours.

### Pricing

`PixelforgePricingService` does all money math with bcmath decimal strings (12 decimal places, no floats, no rounding).

- **Estimate:** a min–max range from `GET /v1/pricing`. Text tokens are `ceil(chars / 4)` ±15%, reference images are 765 tokens each, output tokens are exact per size and quality, and reasoning tokens use the documented min/max for the quality. The stored estimate is the maximum.
- **Actual:** usage × the rates Pixelforge returned for that generation (fixed when it was created) ÷ 1,000,000.
- **User price:** provider cost × (1 + markup / 100), applied once. The markup is stored per generation, so later config changes don't alter past charges.
- **Failed generations:** actual provider and user cost are `0`.

### Webhooks

- The signature (`Pixelforge-Signature: t=…,v1=…`, HMAC-SHA256 of `t.rawBody`) is checked in `VerifyPixelforgeSignature` before parsing, with a 300-second replay window. Invalid signatures get `400` and change nothing.
- The event is stored in `webhook_events` (unique on `provider` + `provider_event_id`) and then acknowledged with `204`. Processing runs in `ProcessPixelforgeWebhook`.
- Duplicate deliveries are acknowledged and skipped. A webhook that arrives before the create request returns is matched by the UUID in `metadata`.

## Local setup

Requirements: PHP 8.2+ with `bcmath` and `pdo_pgsql`, PostgreSQL, Node 20+.

```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
# set DB_* and PIXELFORGE_* in .env (see below)
php artisan migrate
php artisan storage:link
composer run dev        # serve + queue:listen + vite
php artisan schedule:work   # resubmits stuck submissions, in a second terminal
```

Tests run against a PostgreSQL database named `promptedit_testing` (see `phpunit.xml`). They fake every Pixelforge request.

```bash
php artisan test
```

### Pixelforge configuration

| Variable | Purpose |
| --- | --- |
| `PIXELFORGE_BASE_URL` | `https://pixelforge.promptedit.dev/v1` |
| `PIXELFORGE_API_KEY` | API key from the Pixelforge dashboard (shown once at creation). Server-side only. |
| `PIXELFORGE_WEBHOOK_SECRET` | The `whsec_…` signing secret of the same key. |
| `PIXELFORGE_WEBHOOK_TOLERANCE` | Max signature age in seconds (default 300). |
| `PIXELFORGE_MARKUP_PERCENTAGE` | Markup on provider cost (default 25). |
| `PIXELFORGE_TIMEOUT` | HTTP timeout in seconds (default 60). |
| `PIXELFORGE_PRICING_CACHE_TTL` | Seconds to cache `GET /v1/pricing` (default 3600). |

Each Pixelforge API key has its own webhook URL and secret. Use one key per environment.

1. In the Pixelforge dashboard, create a key and copy it into `PIXELFORGE_API_KEY`.
2. Set that key's webhook URL to `https://<public-host>/webhooks/pixelforge` and copy its signing secret into `PIXELFORGE_WEBHOOK_SECRET`.
3. Locally, Pixelforge rejects `localhost` and `.test` URLs, so expose the app with a tunnel (ngrok, Expose or Cloudflare Tunnel) and use the tunnel URL. Without a reachable webhook URL, generations stay queued/processing.
4. Use "Send test event" in the dashboard; the `ping` should appear in `webhook_events` as `ignored`.

## Deployment

1. **PostgreSQL:** set `DB_CONNECTION=pgsql` and `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` (and `DB_SSLMODE=require` for managed databases).
2. **Environment:** `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://your-domain`, a production `PIXELFORGE_API_KEY` and its `PIXELFORGE_WEBHOOK_SECRET`. Prefer `QUEUE_CONNECTION=redis` or `database`, and `CACHE_STORE=redis` or `database` (the cache backs job uniqueness locks and the rate-limit cool-down).
3. **Build and cache:**
   ```bash
   composer install --no-dev --optimize-autoloader
   npm ci && npm run build
   php artisan migrate --force
   php artisan storage:link
   php artisan config:cache && php artisan route:cache && php artisan view:cache && php artisan event:cache
   ```
4. **Queue worker** (Supervisor or equivalent), restarted on each deploy with `php artisan queue:restart`:
   ```bash
   php artisan queue:work --tries=10 --timeout=90 --sleep=1
   ```
5. **Scheduler:** `* * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1`. It runs `generations:resubmit-stuck` every minute.
6. **Webhook:** point the production key's webhook URL at `https://your-domain/webhooks/pixelforge` and send a test event.
